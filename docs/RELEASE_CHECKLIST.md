# Release checklist

Everything that must be true before a build leaves this machine. Items marked **OWNER** need a
decision or a tool this repository cannot drive (InstallShield, a code-signing certificate); the
rest is mechanical.

## 1. The tree

- [ ] Working tree clean, or the intended changes committed — the frozen artifact's
      `BUILD_INFO.json` records `commit` + `worktree_state`, and a release must read `clean`.
- [ ] `git status --short` shows nothing uncommitted that the build is meant to carry.
- [ ] Version bumped where it is read: `pyproject.toml` (`version`), the exe's version resource
      (generated by `scripts/build_exe.py` from `pyproject.toml`), the installer project, and the
      README badge/counts.

## 2. Gates (all four, on the tree that is about to be built)

```
.venv/Scripts/python.exe -m pytest orderflow_system -q          # expect 0 failed
node orderflow_system/desktop/ui/ofx.selftest.js                # expect 0 failed
.venv/Scripts/python.exe scripts/audit_ui_refs.py               # expect AUDIT CLEAN
uvx ruff@0.16.7 check orderflow_system scripts                  # expect All checks passed
```

## 3. Artifact

- [ ] `python scripts/build_exe.py --clean` completes; the log ends with the build stamp path.
- [ ] `dist/<APP>/BUILD_INFO.json` exists and its `commit` is the intended one.
- [ ] Developer harnesses were pruned (`pruned N developer file(s)` in the log — the 33
      `*.selftest.js` files must not be in the payload).
- [ ] `build/` intermediates are **not** shipped: the zip/installer carry `dist/<APP>` only.
- [ ] Smoke the frozen exe with a scratch profile and a free port:

```
set APPDATA=%TEMP%\ofap-smoke
dist\ModFlowOrderFlowAnalysisSuite\ModFlowOrderFlowAnalysisSuite.exe --headless --port 8097
curl http://127.0.0.1:8097/healthz      # {"ok": true, ...}
curl -I http://127.0.0.1:8097/desktop   # 200
```

- [ ] Stop it and confirm the port is released (`netstat -ano | findstr 8097`).
- [ ] `/docs`, `/redoc` and `/openapi.json` answer **404** in the frozen app (F-11).
- [ ] Build the setup (`installer\make_installer.ps1`) and run its install/uninstall journey
      (`installer/README.md` -> "Verification journey").
- [ ] `python scripts/build_exe.py --release` refuses a dirty worktree (F-08): the release stamp
      must read `worktree_state: "clean"` and its `commit` must match the tag being published.
- [ ] After a GUI session, `%TEMP%` holds no `EBWebView` from this app — the profile lives under
      `%APPDATA%\OrderFlowAnalysisPro\webview2` and stale temp profiles are swept at boot
      (F-01/F-02).
- [ ] The payload file count and the installer size quoted in `installer/README.md` and
      `docs/RELEASE_EVIDENCE_v0.1.0-beta.md` are re-derived from THIS `dist/` (F-09);
      `sha256sum dist/*` equals the tables.

## 4. Licensing and provenance

- [ ] `THIRD_PARTY_NOTICES.md` is current: the dependency table, the LGPL-3.0 note for
      `python-telegram-bot`, and the MetaQuotes terms for the bundled `MetaTrader5`.
- [ ] The payload carries a licence text for every bundled package it ships under
      `_internal/*.dist-info/licenses/` — **this is known to be incomplete**; add missing texts to
      the build (`--add-data`) before publishing.
- [ ] `docs/BINARY_PROVENANCE.md` matches the committed binaries (`sha256sum` both, compare).
- [ ] Hashes recorded in the release notes match the artifacts actually uploaded
      (`sha256sum` the exe/zip/installer and paste them; `BUILD_INFO.json` carries the exe's hash).

## 5. Installer (Inno Setup - no licence caveat)

- [x] Built with Inno Setup 6 (`installer/make_installer.ps1` -> `modflow.iss`); the InstallShield
      evaluation-mode MSI is history (F-05).
- [x] WebView2 is chained: the setup detects the runtime in three registry locations and runs
      Microsoft's Evergreen bootstrapper when it is missing (F-06).
- [x] No machine paths: the binary `.ism` and the unused `.prq` were deleted; the installer is text (E-05).
- [ ] Run `scripts\verify_installer.ps1` (one command, 11 PASS/FAIL steps: install -> files, ARP,
      Start Menu, headless boot with `/healthz` 200 and `/docs` 404 -> uninstall -> everything gone,
      user data intact). It passes on this machine; run it on a **clean** machine (fresh Windows
      image or a new user profile) before publishing - escalate to the `cross-platform-installer-testing`
      skill for the VM route.

## 6. Signing - the route is decided; one application is left

The endpoint half is done: `/docs`, `/redoc` and `/openapi.json` are disabled in the packaged build
(verified 404 in the frozen exe; `OFAP_OPENAPI=1` re-enables them for debugging).

For signing, the options were checked against the current rules, and only two are real from
Australia:

| Route | Cost | Verdict here |
|---|---|---|
| **SignPath Foundation** | free for qualifying open-source projects | **Recommended** - this project qualifies (public repo, MIT licence, CI-built artifacts). No personal identification: they verify the binary came from the repository. |
| **OV certificate** (Certum, SSL.com, Sectigo resellers) | ~AU$300-400/yr + ID verification + a hardware token | Fallback if SignPath declines or you want the app signed outside CI. |
| Azure Artifact Signing (formerly Trusted Signing) | US$9.99/mo | **Not available**: individuals are limited to the USA and Canada, organizations to USA/CA/EU/UK - an Australian individual cannot enrol. |
| EV certificate | ~AU$600+/yr | Overkill for a beta; worth it only if you want instant SmartScreen trust. |

**SignPath is wired up and inert until you apply:**

- `apply` - the application lives at signpath.org; the artifact configuration lives at
  `.signpath/artifact-configurations/default.xml` (signs the app exe and the setup in one request;
  commit it at release time - the CI sign job reads it from the tree, so it cannot run until tracked).
- `CI` - the `sign` job in `.github/workflows/ci.yml` is **skipped** until the repository carries
  `SIGNPATH_ORGANIZATION_ID` (a repository variable) and `SIGNPATH_API_TOKEN` (a secret); once set,
  every build signs automatically and uploads `signed-binaries`.
- `local` - `scripts\sign_release.ps1 -Thumbprint <sha1>` (or `-PfxPath`) signs and verifies
  locally with a certificate you own; it fetches signtool when it is absent and, with no
  certificate, exits 3 printing exactly what is missing.

Until one of these lands, the binaries stay unsigned and SmartScreen warns on every download.

## 7. Publish

- [ ] Tag the commit; the tag must match `BUILD_INFO.json`.
- [ ] Upload the zip + installer + SBOM; paste the hashes into the release page.
- [ ] Re-verify one downloaded artifact's hash from a second machine or a clean directory.
